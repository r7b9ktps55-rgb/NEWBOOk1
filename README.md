# Book Hub

Личный сайт, который превращает книги (PDF, EPUB, FB2, DjVu, DOCX, TXT…) и статьи по ссылке в конспекты, цитаты, сжатые пересказы и другие заметки для Obsidian с помощью Gemini.

- Загружаете файл книги (можно перетащить) или ссылку → задача попадает в очередь.
- Для каждой книги выбираете, что сделать (можно сразу несколько):

  | Формат | Что получится |
  |---|---|
  | Подробный конспект | Главная идея, концепции, разбор по главам, цитаты, план действий, связанные темы `[[...]]` |
  | Кратко на 1 страницу | 400–500 слов: суть и 5 главных идей |
  | Ключевые моменты | 15–30 главных мыслей с пояснениями + «три вещи, которые надо запомнить» |
  | Лучшие цитаты по темам | Дословные цитаты, сгруппированные по 4–8 темам книги |
  | Герои (ГГ и персонажи) | Главный герой, его арка и мотивация, второстепенные персонажи, отношения, конфликт |
  | Карточки для повторения | 20–40 карточек `Вопрос::Ответ` для плагина Spaced Repetition |
  | Сжатие ×2 / ×3 / ×4 / ×5 | Пересказ всей книги, сокращённый в 2–5 раз, с сохранением авторского голоса и порядка глав |

- Каждый день в заданное время (или по кнопке) Gemini разбирает очередь. Очередь обновляется на странице сама, а когда заметки готовы — появляется уведомление.
- Каждый формат — отдельная заметка: `Книга - Автор (цитаты).md`, `Книга - Автор (сжатие x3).md` и т.д. Уже разобранной книге можно позже заказать другие форматы.
- Заметку можно прочитать на сайте, скачать, открыть в Obsidian или автоматически отправить в Git-репозиторий хранилища.

Результаты проверки перед запуском (23 пункта: безопасность, данные, эксплуатация, дизайн) — в [`docs/AUDIT.md`](docs/AUDIT.md).

Оформление — по дизайн-системе в [`DESIGN.md`](DESIGN.md) (стиль Readwise: бумажный фон, заголовки с засечками, синий акцент и жёлтый маркер), анимации на [Motion](https://motion.dev).

## Важно до установки

- **Где будет работать сервер.** Gemini API доступен не во всех странах — например, с российских IP-адресов запросы отклоняются («User location is not supported»). Запускайте Book Hub на сервере в поддерживаемой стране ([список регионов](https://ai.google.dev/gemini-api/docs/available-regions)).
- **Что уходит в Google.** Текст книг и статей отправляется в Gemini. На бесплатном тарифе Google может использовать загруженное для улучшения своих продуктов, поэтому личные документы лучше разбирать на платном тарифе.
- **Модель.** По умолчанию `gemini-flash-latest` — псевдоним, который всегда указывает на актуальную модель Flash (о смене версии Google предупреждает письмом за две недели). Конкретные модели со временем выводятся из обращения: например, запросы к `gemini-2.5-flash` с 1 декабря 2026 года перенаправляются на более новую модель по её цене. Если важна предсказуемость цены и стиля ответов, закрепите модель из [списка](https://ai.google.dev/gemini-api/docs/models) в `GEMINI_MODEL` и следите за [страницей устаревших моделей](https://ai.google.dev/gemini-api/docs/deprecations).

## Быстрый старт (Docker)

```bash
git clone https://github.com/r7b9ktps55-rgb/NEWBOOk1.git bookhub
cd bookhub
cp .env.example .env
nano .env                    # GEMINI_API_KEY и WEB_PASSWORD (не короче 10 символов) — обязательно
mkdir -p data && sudo chown -R 1000:1000 data   # контейнер работает не от root
docker compose up -d --build
```

Откройте http://localhost:8080, логин `me` (или `WEB_USER`), пароль — `WEB_PASSWORD`.

Чтобы открыть сайт с телефона в той же Wi-Fi-сети, поставьте `BIND=0.0.0.0` в `.env` и выполните `docker compose up -d`. На VPS так не делайте: Docker обходит правила файрвола (UFW), и сайт окажется открыт всему интернету по HTTP.

### Доступ из интернета по HTTPS

Пароль передаётся с каждым запросом, поэтому из интернета — только через HTTPS. В комплекте есть Caddy: он сам получит и будет продлевать сертификат.

1. Направьте домен (например, `books.example.com`) на IP сервера и откройте порты 80 и 443.
2. В `.env`: `DOMAIN=books.example.com`, `BIND=127.0.0.1`, `FORWARDED_ALLOW_IPS=*` (чтобы ограничение попыток входа видело настоящие адреса).
3. `docker compose --profile https up -d`

Проверка: `http://books.example.com` должен перенаправлять на `https://`, а `curl -sI https://books.example.com | grep -i strict-transport` — показывать `max-age`.

## Без Docker

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env
.venv/bin/uvicorn bookhub.main:create_app --factory --port 8080
```

Запускайте один процесс (без `--workers`): очередь и расписание рассчитаны на одного исполнителя.

## Настройки (`.env`)

| Переменная | Что делает |
|---|---|
| `GEMINI_API_KEY` | Ключ Gemini, https://aistudio.google.com/apikey |
| `WEB_USER`, `WEB_PASSWORD` | Вход на сайт. Пароль — не короче 10 символов. После 10 неверных попыток вход с этого адреса блокируется на 10 минут |
| `GEMINI_MODEL` | Модель, по умолчанию `gemini-flash-latest` (всегда актуальная Flash) |
| `DEFAULT_FORMATS` | Форматы, отмеченные по умолчанию: `summary,brief,key,quotes,characters,cards,x2,x3,x4,x5` |
| `DAILY_RUN_TIME` | Время ежедневного разбора `ЧЧ:ММ`; `off` — выключить. Пропущенный разбор (сервер был выключен) выполняется после запуска |
| `DAILY_BATCH_SIZE` | Сколько книг разбирать за раз |
| `MAX_REQUESTS_PER_JOB` | Потолок запросов к Gemini на одну книгу (по умолчанию 60). Проверяется **до** первого запроса |
| `DAILY_REQUEST_LIMIT` | Потолок запросов в сутки (по умолчанию 300, `0` — без лимита). Когда он исчерпан, книга возвращается в очередь и разбор продолжится завтра |
| `TIMEZONE` | Часовой пояс, например `Europe/Saratov` |
| `NOTIFY_URL` | Куда слать уведомления об ошибках и итогах разбора (см. ниже) |
| `OBSIDIAN_VAULT_NAME` | Имя хранилища для кнопки «Открыть в Obsidian» |
| `OBSIDIAN_VAULT_SUBFOLDER` | Папка для конспектов внутри хранилища (`Books`) |
| `GIT_REPO_URL`, `GIT_TOKEN`, `GIT_BRANCH` | Автоматический push заметок в репозиторий хранилища |
| `BACKUP_TIME`, `BACKUP_KEEP`, `BACKUP_DIR`, `BACKUP_BOOKS` | Ежедневная резервная копия: во сколько, сколько хранить, куда, класть ли исходные книги |
| `TRASH_DAYS` | Сколько дней удалённое лежит в корзине (по умолчанию 30) |
| `MAX_UPLOAD_MB` | Лимит размера одного файла книги |
| `BIND`, `PORT`, `DOMAIN`, `FORWARDED_ALLOW_IPS` | Где слушает сайт и настройки HTTPS (только Docker) |

### Расходы на Gemini: что настроить в Google

Приложение само не даёт одной книге съесть больше `MAX_REQUESTS_PER_JOB` запросов, а всем вместе — больше `DAILY_REQUEST_LIMIT` в сутки. Сколько запросов уже ушло сегодня, видно в разделе «Очередь». Жёсткий потолок денег ставится в Google:

1. https://aistudio.google.com/apikey — посмотрите тариф проекта вашего ключа. На бесплатном деньги не списываются, при исчерпании лимита API отвечает ошибкой 429.
2. На платном тарифе: в AI Studio → **Spend** → **Monthly spend cap** укажите месячный предел (например, 5–10 $).
3. https://console.cloud.google.com/billing → **Budgets & alerts** → бюджет с письмами на 50 %, 90 % и 100 %.
4. Ключ: **APIs & Services → Credentials** → ограничьте его только Generative Language API.

Ориентир: книга на 300 страниц — по 1 запросу на каждый обычный формат и около 15 запросов на каждый уровень сжатия.

### Уведомления на телефон

`NOTIFY_URL` — сообщения об ошибках разбора, проблемах с Git и резервной копией и об итогах ежедневного разбора:

- **ntfy** (проще всего): установите приложение ntfy, придумайте длинное случайное имя топика и укажите `NOTIFY_URL=https://ntfy.sh/ваш-случайный-топик`.
- **Telegram**: `NOTIFY_URL=https://api.telegram.org/bot<токен>/sendMessage?chat_id=<ваш id>&text={text}`.
- Любой вебхук, принимающий POST с текстом.

### Git-синхронизация с Obsidian

1. Создайте приватный репозиторий для хранилища (или используйте существующий — старые заметки сохранятся).
2. Создайте fine-grained токен GitHub с доступом **Contents: Read and write** только к этому репозиторию и со сроком действия.
3. Пропишите `GIT_REPO_URL` и `GIT_TOKEN`. Токен передаётся git через переменные окружения: его нет ни в `.git/config`, ни в списке процессов, ни в сообщениях об ошибках.
4. На компьютере/телефоне подтягивайте изменения плагином Obsidian Git.

Если заметку правили в Obsidian, а на сайте в это время удалили или пересоздали, при конфликте побеждает версия из репозитория — ваши правки не теряются.

## Какие файлы принимаются

| Формат | Как читается |
|---|---|
| PDF | Отправляется в Gemini целиком — модель видит и текст, и сканы, таблицы, картинки |
| DjVu | Конвертируется в PDF программой `ddjvu` (в Docker-образе уже есть; без Docker — пакет `djvulibre-bin`) |
| EPUB | Главы в порядке книги, заголовки, название и автор из метаданных. EPUB с DRM не читается |
| FB2, FB2.ZIP | Разделы и заголовки, стихи, эпиграфы; сноски пропускаются. Кодировка (UTF-8, windows-1251) определяется сама |
| DOCX | Абзацы и заголовки |
| TXT, MD | Кодировка определяется автоматически (UTF-8, windows-1251, KOI8-R…) |
| HTML | Весь текст страницы с заголовками (удобно для книг с lib.ru) |

MOBI, AZW3 и старый DOC не поддерживаются — переведите их в EPUB или DOCX, например, в Calibre. Книги из текстовых форматов читаются локально, и в Gemini уходит только текст: это дешевле, чем отправлять файл.

## Как работает сжатие ×N

Книга режется на части примерно по 6000 слов (для PDF — не больше 30 страниц), и каждая часть пересказывается отдельным запросом с точной целью по объёму: «≈ 2000 слов» для 6000 слов при ×3. Так длинные книги не упираются в лимит ответа модели. Для сканов без текстового слоя объём оценивается как 300 слов на страницу. В начале заметки — сколько слов было и сколько стало.

Перед первым запросом приложение считает, сколько их понадобится, и останавливается, если это больше `MAX_REQUESTS_PER_JOB`. При ошибке 429 оно само ждёт и повторяет; если задача всё же упала, «Повторить» продолжит с недоделанных форматов.

## Свой промпт

Положите текст в `data/prompts/<формат>.md` (`summary.md`, `quotes.md`, `characters.md`…) — он заменит встроенный промпт этого формата. Первая строка ответа модели должна быть `FILENAME: Название - Автор`. Поля frontmatter (`title`, `author`, `book`, `format`, `tags`, `source`…) приложение добавляет само.

## Данные, корзина и резервные копии

```
data/
  inbox/            книги в очереди (можно класть файлы сюда напрямую)
  archive/          обработанные книги
  obsidian_vault/   хранилище; конспекты в Books/
  trash/            корзина: удалённые заметки и книги (очищается через TRASH_DAYS дней)
  backups/          резервные копии (или BACKUP_DIR)
  cache/            DjVu, сконвертированные в PDF (чистится сам)
  bookhub.db        очередь, история и счётчики
```

- **Удаление** не стирает файл сразу: он попадает в корзину, а на странице появляется кнопка «Отменить».
- **Все заметки одним архивом** — кнопка «Все заметки (.zip)» в библиотеке.
- **Резервная копия** делается каждый день в `BACKUP_TIME` (по умолчанию 03:30): снимок базы (безопасно на работающем сайте), хранилище вместе с `.git` и свои промпты. Исходные книги — только с `BACKUP_BOOKS=1`. Хранится `BACKUP_KEEP` последних копий.
- Копия на том же диске не спасёт от его поломки: укажите `BACKUP_DIR` на другом диске или регулярно забирайте `data/backups` к себе (например, `rsync` или облако).

Вручную:

```bash
docker compose exec bookhub python -m bookhub.backup create          # сделать копию сейчас (--books — с книгами)
docker compose exec bookhub python -m bookhub.backup list            # список копий
```

Восстановление (сайт остановлен):

```bash
docker compose stop
docker compose run --rm bookhub python -m bookhub.backup restore data/backups/bookhub-….tar.gz --force
docker compose start
```

Проверить восстановление, не трогая рабочие данные: распакуйте копию в отдельную папку и запустите вторую копию сайта на другом порту:

```bash
mkdir -p ~/restore-test && sudo chown 1000:1000 ~/restore-test
docker run --rm -e WEB_PASSWORD=test-password -e DAILY_RUN_TIME=off -e BACKUP_TIME=off \
  -v ~/restore-test:/app/data -v "$PWD/data/backups:/backups:ro" bookhub-bookhub \
  python -m bookhub.backup restore /backups/bookhub-….tar.gz
```

Перед обновлением схемы базы приложение само сохраняет её копию рядом (`bookhub.db.bak-v<версия>`): чтобы откатиться на старую версию программы, остановите сайт и верните этот файл на место `bookhub.db`.

## Проверка здоровья

`GET /health` (без пароля) отвечает `{"ok": true, "db": true, "disk": true, "queue": true}` или 503, если база недоступна, на диске меньше 200 МБ или задача зависла дольше 30 минут. Docker использует его в `HEALTHCHECK`; статус виден в `docker compose ps`.

## Разработка

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check bookhub tests
```

Тесты не ходят в Gemini — модель подменяется заглушкой. Точные версии всех зависимостей для Docker лежат в `requirements.lock` (с хешами); после изменения `requirements.txt` пересоберите его:

```bash
uv pip compile requirements.txt --python-version 3.12 --generate-hashes --exclude-newer <дата две недели назад> -o requirements.lock
```

Облегчённая сборка Motion пересобирается скриптом `scripts/build-motion.sh`.
