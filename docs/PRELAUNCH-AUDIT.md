# Предстартовый аудит Book Hub (8 зон)

**Что проверялось.** Код коммита `640bfca`, ветка `claude/obsidian-book-hub-cloud-setup-x1p7p9`. Адрес боевого сайта не указан (в задании был шаблон `{URL}`), поэтому проверялись 8 локальных экземпляров, запущенных как в продакшене:

- uvicorn `--proxy-headers --workers 1`;
- HTTPS-фронт Caddy 2.10.2 с конфигом из репозитория, на локальном домене с внутренним CA.

**Правила.** Каждая зона проверялась на своём экземпляре, только на чтение. Учётные данные тестовые, книги сгенерированные, нагрузка — не больше нескольких запросов в секунду.

**Gemini заменён локальной имитацией.** Код сайта не менялся: адрес подставлялся через `GOOGLE_GEMINI_BASE_URL`. Поэтому смысловое качество заметок и время работы настоящей модели не оценивались.

**Ограничение имитации.** Она не разбирала inline-PDF в URL-safe base64, который шлёт официальный SDK. Из-за этого сжатие PDF и DjVu частями на стенде обрывалось («Server disconnected…»). Это дефект стенда, а не сайта. Но реакция сайта на обрыв (нет повтора, английский текст ошибки) — настоящая, она вынесена в находки.

**Прерывания.** Аудит дважды прерывался исчерпанием лимита API, и контейнер дважды перезапускался. Всё, что агенты не успели проверить, перечислено в разделе 4 как «не проверено». Пройденным такие пункты не считались.

Подробные отчёты, скриншоты и скрипты лежат вне репозитория, в рабочей папке аудита (`scratchpad/audit2/agentN/`).

## 2. Проблемы

### 2.1. Блокирующие (Critical и High)

| ID | Зона | Описание | Доказательство | Что сделать |
|---|---|---|---|---|
| INF-01 | Инфра | В `.env.example` строка `FORWARDED_ALLOW_IPS=` пустая. С ней uvicorn в Docker не доверяет Caddy и видит всех посетителей под одним адресом — адресом контейнера Caddy. 10 неверных паролей от кого угодно блокируют вход всем на 10 минут, включая владельца с верным паролем. Порт 8080 не публиковать. |

### 2.2. Medium

| ID | Описание |
|---|---|
| INF-02 | Значение `FORWARDED_ALLOW_IPS=*` позволяет прямому клиенту (минуя Caddy, а при `BIND=0.0.0.0` — любому в локальной сети) подставлять X-Forwarded-For и обходить лимит входа. Вдобавок `_fails.clear()` при 10 000 адресах стирает все счётчики. |
| UPL-01 | Заметка с длинной цепочкой `[[` без закрытия отрисовывается квадратично (16 КБ — 45 с, 64 КБ — около 12 мин). Отрисовка идёт в цикле событий, и всё это время сайт стоит, включая `/health`. Такая строка может попасть в заметку из дословной цитаты или через правку в Obsidian. |
| UPL-02 | Лимит распаковки (128 МБ на главу) не ограничивает память при разборе lxml: около 64 МБ ОЗУ на 1 МБ плотного HTML. EPUB весом в сотни КБ может потребовать гигабайты памяти, вплоть до OOM. Лимита `mem_limit` в compose нет. |
| FUN-02 | Сообщение «Удалено — файл лежит в корзине» показывается и для задачи с ошибкой (её файл уже в archive, в корзину ничего не попадает), и для задачи «в работе» (она вообще не удаляется). |
| FUN-03 | Таблицы FB2 выпадают из текста, который получает модель. |
| FUN-04 / UPL-06 | PDF с паролем не проверяется. Для конспекта он уходит в Gemini и даёт мусорную заметку. Для сжатия пользователь видит ошибку на английском: «File has not been decrypted». |
| FUN-05 / PERF-02 / UI-01 | Сетевые ошибки (обрыв, таймаут) не повторяются, повтор есть только для 429 и 5xx. Готовые части сжатия теряются, и после «Повторить» за них снова надо платить. Ошибка выводится как сырой английский `str(exc)`. |
| PERF-01 | Потолок `MAX_REQUESTS_PER_JOB=60` виден только после «Разобрать». К этому моменту файл уже в archive, а форматы у задачи поменять нельзя. |
| OBS-01 | Строка «Название - Автор» обрезается до 100 символов целиком, поэтому у длинных названий слово рвётся посередине и пропадает автор. |
| OBS-02 | Когда выбрано только сжатие, метаданные файла (автор) модели не передаются, и автор получается «Неизвестно». |
| OBS-06 / PERF-03 | Если URI заметки длиннее 60 000 символов (≈1,5 тыс. слов кириллицы), кнопка «В Obsidian» молча исчезает. При этом URI всё равно строится на каждый показ, а страница сжатия ×2 открывается 150–350 мс. |
| UI-02 / UPL-04 | Сообщение об отклонённых файлах не говорит, какой файл и почему, и исчезает через 4,5 с. Лимит не уточняет, что 200 МБ — на один файл. При превышении 1000 файлов ответ приходит на английском. |
| UI-03 | Сообщение «Нет связи с сервером» не объявляется экранным диктором (нет `role="status"`) и не видно при прокрутке. |
| SEO-01 | «Сделать ещё…» без выбранного формата перекидывает на главную с чужим сообщением «Выберите файл книги…». |
| SEO-02 / FUN-07 / UI-10 | У всех форматов одной книги одинаковые `<title>` и `<h1>`, а у одной книги из разных файлов — неразличимые карточки. Автор из `<meta name="author">` HTML не читается, вместо него показывается «Неизвестно». |
| SEO-03 | Страница 401/429/413 — единственная, которую видит посетитель без пароля. У неё нет `lang` и viewport, поэтому на телефоне она мелкая. |
| SEO-04 | README пишет, что задача зависла через «30 минут», а в коде 60. |
| SEO-05 | В README описана проверка восстановления на второй копии сайта, но нет команды её запуска. |
| LEG-04 | Подвал неполон. На сервере хранятся и книги; PDF и DjVu уходят в Google файлом целиком; названия уходят в Git и уведомления. |
| LEG-05 | Нет ссылки на условия Gemini API. Не описаны Files API и объём отправки: текст книги уходит заново на каждый формат. |
| LEG-06 | Удаление заметки не стирает её из истории Git. Названия книг попадают в сообщения коммитов. Удалённая заметка может вернуться из репозитория. |

### 2.3. Low (кратко)

- **Инфра:**
  - INF-03 / SEO-07: `max_size 1010MB` в Caddy — десятичные мегабайты, строже лимита приложения; нужно `1010MiB`.
  - INF-04: битый `Origin` даёт 500, и у ответа 500 нет заголовков безопасности.
  - INF-05: в ответах guard нет `frame-ancestors` и `Referrer-Policy`, `Permissions-Policy` нет нигде.
  - INF-06: заголовки `Server` и `Via`.
  - INF-07 / SEO-10: `/health` открыт наружу; `HEAD` даёт 405.
  - INF-08: `/download` и `/export.zip` отдаются с `no-cache` вместо `no-store`.
  - INF-09 / SEO-08: нет `robots.txt` и `X-Robots-Tag: noindex`.
  - INF-10: `alt-svc h3` объявлен без UDP 443; в compose нет `no-new-privileges` и `cap_drop`.
  - SEO-06: при пустом `DOMAIN` Caddy падает с непонятной ошибкой.

## 3. Что уже работает

- **Периметр.**
  - HTTP→HTTPS: 308 с сохранением пути.
  - Только TLS 1.2 и 1.3, AEAD и PFS. HSTS на всех ответах, включая ошибки.
  - Строгий CSP без нарушений в браузере.
  - Без пароля доступны только `/static/` и `/health`.
  - `.env`, `.git`, база, бэкапы и `/docs` закрыты. Листинга и обхода каталогов нет.
  - Страницы ошибок без стек-трейсов и версий.
  - Контейнер работает не от root, зависимости ставятся с хешами, секретов в истории нет.
- **Загрузка.**
  - Тип проверяется по белому списку и сигнатуре; exe, html и svg под видом книги отклоняются.
  - Лимит размера работает и для chunked-запросов. Content-Length 1,1 ГБ отклоняется с 413 до чтения тела.
  - Временные файлы удаляются.
  - Имена безопасны: `../`, NUL и RLO обрабатываются, имя ограничено по байтам.
  - Zip-бомбы, XXE и billion laughs дают понятную ошибку.
  - XSS (25 вариантов) не выполняется ни на одной странице.
  - SSRF блокируется. CSRF даёт 403.
- **Сценарий.**
  - Загрузка одного и нескольких файлов, drag-and-drop, загрузка с телефона.
  - Живая очередь с прогрессом.
  - Сбой одной книги не останавливает очередь, а готовые форматы сохраняются.
  - Кириллица из cp1251 читается правильно.
  - Одна заметка на формат, при конфликте имён добавляется «(2)».
  - «Скачать .md», «Скопировать», «В Obsidian» и ZIP работают корректно.
- **Obsidian.**
  - Frontmatter валиден в 4 парсерах у 31 из 32 заметок (исключение — OBS-04).
  - UTF-8 без BOM, переводы строк LF.
  - В ZIP стоит флаг UTF-8, `Content-Disposition` по RFC 5987.
  - Callouts, задачи и wikilinks сохраняются.
- **Производительность.**
  - Главная отвечает за 4–11 мс (155 заметок), `/live` — за 4–11 мс.
  - Lighthouse: LCP 2,0 с, CLS 0, TBT 0.
  - 5 параллельных загрузок и двойное «Всю очередь» проходят без 5xx и двойной обработки.
  - Память — до 141 МБ.
  - Накладные расходы сайта на книгу в 100 тыс. слов — секунды.
- **Интерфейс.**
  - Горизонтальной прокрутки нет при ширине 320–1280 px в обеих темах.
  - axe — 0 нарушений, контраст ≥ 4,5:1 (кроме UI-05).
  - Клавиатурный порядок и видимый фокус в порядке, кнопки подписаны, уведомления идут через `aria-live`.
- **Приватность.**
  - Cookies и хранилищ браузера нет.
  - Внешних запросов нет: шрифты и скрипты локальные, лицензии рядом.
  - PDF удаляется из Files API после разбора.
  - README честно говорит об отправке текста в Google.
- **Почта: неприменимо.** Сайт не отправляет писем, уведомления идут через ntfy, Telegram или вебхук.

## 5. Вердикт: «готово с оговорками»

**Для личного сайта одного владельца:**

- критических проблем нет;
- периметр, загрузка и XSS-защита в хорошем состоянии;
- основной сценарий работает.

**До публикации надо закрыть:**

- INF-01: иначе любой посетитель может держать владельца без доступа к сайту;
- FUN-01;
- лучше также Medium-проблемы устойчивости (UPL-01, UPL-02, FUN-05 / PERF-02) и понятность ошибок.

**Давать пароль другим людям нельзя,** пока не решены LEG-01, LEG-02, LEG-03 и LEG-07.

## Чек-лист перед публичным запуском

- [ ] `FORWARDED_ALLOW_IPS` = подсеть Caddy (фиксированная подсеть в compose), не пусто и не `*`; порт 8080 наружу не опубликован (INF-01, INF-02)

- [ ] `DOMAIN` задан; DNS A/AAAA указывают на сервер; запись www не создана, или есть редирект (SEO-06)
- [ ] После запуска: `curl -sI http://ДОМЕН` → 308; `curl -sI https://ДОМЕН | grep -i strict`; сертификат Let's Encrypt действителен (команда `openssl` из раздела 4)
- [ ] Снаружи открыты только 80 и 443 (`nmap -Pn`)
- [ ] Caddy: `max_size 1010MiB`; `X-Robots-Tag: noindex`, `robots.txt` с `Disallow: /`; закрыть `/health` снаружи или разрешить его только монитору (INF-03, INF-07, INF-09)
- [ ] Исправлено «Отменить» в очереди (FUN-01)
